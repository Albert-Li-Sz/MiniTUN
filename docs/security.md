# 安全设计状态

MiniTun 提供受保护的本地控制面、经过认证的 TLS 控制会话、按代次划分的 TLS
Worker Pool、有界的原始 TCP 中继数据面，以及受跟踪的优雅关闭。

已实现的本地保护包括：

- 严格、有界的 UTF-8 JSON 和每连接单请求 IPC；
- 位于可信、守护进程所有目录中的 `0660` Unix 套接字；
- 安全替换陈旧套接字、连接上限、期限和异常隔离；
- 由守护进程所有且权限精确为 `0600` 的状态数据库与凭据数据库；
- 拒绝符号链接、多重硬链接、非普通文件、所有权不匹配以及组/其他用户可写的父目录；
- 在 SQLite 打开过程中校验描述符/路径 inode，以检测路径替换；
- 绑定凭据值、SQLite 安全删除，以及拒绝错误模式而非破坏性重建；
- 无回显交互式 Token 输入和显式 `--token-stdin` 自动化；
- 常规输出、JSON 响应、状态行、错误和日志均不包含 Token；
- 主动清除含 Token 的 CLI、IPC 和 `SecureString` 缓冲区。

凭据数据库受权限保护但未加密。root、守护进程账户、具有同等权限的失陷进程、
备份或存储快照仍可能暴露凭据。部署时必须保护主机和文件系统，不得将凭据文件放在
共享目录中。

远程控制传输要求 TLS 1.2 或更高版本、主机名校验、HMAC-SHA256 质询认证、有界
nonce 重放保护、时钟偏差校验、失败限速、新会话代次和心跳期限。每个公网服务端
都有隔离的守护进程会话、重连控制器和 Worker Pool。

公网监听器只使用数值绑定地址，要求有限的 `--allow-ports` 策略，并实施逐客户端
已注册隧道上限和按代次划分的监听器所有权；失败稳定映射为 `permission_denied`、
`resource_exhausted` 和 `remote_port_in_use`。本地目标主机与端口绝不会进入
控制协议。

Worker 身份会根据当前会话代次校验，同时实施会话级和全局空闲上限、有界公网套接字
等待、自动补充和空闲过期。代次被替换时，陈旧 Worker 会立即关闭。

被分配的 Worker 只解析本地持久化的隧道目标。远程消息无法选择任意本地主机或端口。
本地连接失败使用通用错误；中继在每个方向使用固定 16 KiB 缓冲区，空闲期限会限制
无数据连接的存活时间。

MiniTun 强制执行逐客户端和全局公网中继配额、守护进程全局 Worker/中继连接预算、
由 strand 串行化的会话所有权、有界的待处理连接生命周期、尽力而为的 `GOAWAY`
以及受期限约束的中继排空。容量使用可移动但不可复制的租约，因此拒绝、超时、取消、
半关闭和普通拆除都不会造成配额泄漏或重复释放。

完整测试套件已通过 AddressSanitizer、UndefinedBehaviorSanitizer 和
ThreadSanitizer。TLS 流对象会保持存活，直至所有已取消的异步操作完成，包括
`GOAWAY` 关闭期间。专用 libFuzzer 目标覆盖远程帧、IPC 帧、IPC JSON、端点和
端口范围。
